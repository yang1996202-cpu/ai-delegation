# ai-delegation — AI 派活验收器

> 把"给 AI 派活"从碰运气变成有纪律的四步循环：**分诊 → 派活 → 验收 → 迭代**。

## 它解决什么问题

AI 把"产出"的成本打到近乎为零，但没人教你"管理"。用 AI 的四种常见死法：

1. **派活前不判断**——把 AI 干不了的活（依赖你的私有经验）当它能干的直接甩过去
2. **指令自相矛盾**——既要"全面详尽"又要"简短精炼"，AI 随机牺牲一条要求，且不告诉你牺牲了哪条
3. **验收全凭感觉**——"看着挺好"就采纳，识别不了"一本正经的胡说"（结构完整、语言流畅、但论证推不出结论）
4. **迭代没纪律**——第一稿直接用，或改两轮就放弃

这四条恰好对应管人时人人都懂的管理动作：**岗位匹配、任务简报、验收标准、反馈迭代**。本 skill 把这套最小管理协议装进人机协作。核心公式来自《AI领导力》（姚金刚/乔向阳）：

> **AI 输出质量 = 你的输入结构 × 你的判断标准。AI 出算力，人出框架和品控。**

当 AI 的生成速度是你的一万倍时，你唯一能赢的就是**品控的权力**。

## 适合 / 不适合

**适合你，如果：**
- 你高频用 AI 产出知识型交付物（调研报告、文章、方案、周报……领域无关）
- 产出经常"看着挺好"但总差口气，说不清差在哪
- 你想要一套可执行的验收标准，而不是"感觉还行"

**不适合，如果：**
- 你要解决的是"内容怎么搭结构"——那是 [structure-refactor](https://github.com/yang1996202-cpu) 的活（本 skill 的黄金圈只是它的提示词翻译）
- 你想把重复经验沉淀成 skill——收口请走 [skill-extractor](https://github.com/yang1996202-cpu)，本 skill 明确不重写沉淀逻辑

## 需要输入什么

- 一个具体任务 + 你的目的（给谁用、用来做什么决定）
- 可选：你的私有背景材料——如果任务依赖只有你知道的经验（"AI 盲区"型），投喂质量直接决定产出质量

## 输出长什么样

本 skill 是**协作纪律**，嵌入在派活对话中执行，不产生独立产物。当你说"给刚才的产出做个体检"时，输出三样东西：

1. **象限判定**——这个任务落在乔哈里视窗哪一格（附判定依据）
2. **四工位检查表**——逐项 过/不过 + 证据
3. **回炉指令**——一条可直接粘贴使用的改进版提示词，不是泛泛建议

## 典型提示词

```
帮我写/做/生成 X          ← 触发分诊：先判这活该怎么派
这个活让 AI 干靠谱吗       ← 只做工位1，给派活建议
给刚才的产出做个体检        ← 跑工位3 验收，输出检查表
AI 写的不行，怎么改提示词    ← 工位4：定位问题归哪个工位，给回炉指令
```

## 工作流：和其他 skill 怎么咬合

一次完整的派活循环里，三个 skill 各司其职（引用全部**单向**，无循环依赖）：

```
①分诊(乔哈里定象限) → [素材散？] → structure-refactor 搭骨架
②派活(黄金圈+扫矛盾) → AI 产出 → ③验收(4A 门控·"证"的两问)
     ├─ 验收不过 → 定位归哪个工位 → 回炉改指令
     └─ 验收过 且 同类任务第三次以上 → skill-extractor 沉淀
```

- **structure-refactor**（派活前调用，可选）：素材"有深度但散"、或 How 列不出干净步骤时，先搭金字塔骨架，再一步翻译成黄金圈指令——结论→Why、分层理由→How、验收标准→What。它不反向依赖本 skill，随时可被任何流程单独调用
- **skill-extractor**（收口时调用，不是每轮都跑）：同类重复任务做到第三次以上才触发——把派活经验沉淀成可复用的 skill，对话式迭代就此停止。它是循环的**出口**，不是站点
- **lead-card** 等产出型 skill：它们是工位3 验收表的**实例**——任何 AI 产出型 skill 都可以把 4A 验收表内化为自己产出的最后一道自检（lead-card v0.5.0 已内置）

| 版本 | 反馈 | 修正 |

## 如何安装

```bash
# WorkBuddy / 兼容 agent skills 目录
git clone https://github.com/yang1996202-cpu/ai-delegation.git ~/.workbuddy/skills/ai-delegation
```

重开会话后生效。

**没有 structure-refactor / skill-extractor？照常可用。** 这两个是作者生态内的 skill，本 skill 对它们的引用全部可降级：你的环境里没有时，Agent 会跳过对应步骤（派活前搭骨架 / 收口沉淀），四工位主流程完整不受影响。想要完整体验，等这两个 skill 后续开源。

## 知识源与边界

- 方法论锚定：《AI领导力》（姚金刚/乔向阳）——乔哈里视窗分诊、Prompt黄金圈、4A 评估法、迭代原则
- 验收探针同源：《结构思考力》（李忠秋）"证"的两问——验金字塔和验 AI 是同一个动作
- 本 skill 是**协议层**：不含内容结构方法（归 structure-refactor）、不含经验沉淀方法（归 skill-extractor）、不绑定任何业务领域
